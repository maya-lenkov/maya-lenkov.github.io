The problem

Searching for internships involves more than finding a good role. There are postings across different platforms, repeated profile fields, tailored writing, and a growing list of applications to track. I started building this agent to bring that work into one place.

A workflow built around review

The project brings discovery, writing, and form preparation into a local portal. Its current README describes a three-step application desk:

01 / FEEDFind and choose

Review discovered roles and choose which ones to prepare.

02 / WAITING TO SUBMITPrepare and inspect

Review written responses, resolve missing information, and inspect prepared forms.

03 / APPLIEDKeep a record

Track confirmed or manually recorded submissions and their spreadsheet sync state.

The technical decisions

  • Ground writing in evidence. Tailored drafts use resume material and checks intended to catch unsupported claims. Applicant review remains part of the process.
  • Keep final submission manual. The current extension workflow prepares supported forms and hands the employer page back to the user.
  • Retain application state. SQLite stores history and queued work so an interrupted session does not simply disappear.
  • Pause when the form is uncertain. Unknown answers, unsupported controls, sign-in, and security checks require attention rather than a guessed answer.
  • Separate preparation from confirmation. Opening or filling a form does not count as a successful application.

Where it stands

This is my largest agent project, and I’m continuing to develop it while exploring its potential as a startup. The README documents discovery sources, a local portal, resume and writing management, browser adapters, a Chrome extension workflow, and Google Sheets tracking.

Support depends on the employer’s application platform and page layout. The documentation describes synthetic browser tests, which do not establish that every live employer flow works. This portfolio is a project overview, not a live application service.
